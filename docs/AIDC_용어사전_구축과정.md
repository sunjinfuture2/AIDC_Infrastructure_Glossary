## 2. 작업 방식 — 사람과 AI의 반복 루프

- **요청**: 담당자가 화면 캡처에 빨간 선으로 표시하고 "이 부분을 이렇게" 식으로 한국어로 지시

- **승인**: 담당자가 PR을 직접 검토·머지 (AI는 머지하지 않음) → GitHub Pages 자동 배포
- **특징**: 한 번에 1~4개의 작은 수정을 받아 PR 1건으로 처리. 하루에 최대 19건(08-18)까지 회전

## 3. 시스템 구조

| 구성 | 내용 |
|---|---|
| 복층 모드 | React 18 + Vite + Zustand(상태) + three.js r169. 3D 뷰포트는 명령형 three.js 코드로 구현 |
| 단층 모드 | 담당자가 만든 원본 HTML(three.js r128)을 iframe으로 그대로 실행 |
| 배포물 | 저장소의 `/3d` 폴더에 정적 빌드를 커밋 → GitHub Pages |
| 주요 파일 | `Viewport.jsx`(씬·카메라·선택·층 필터), `buildFacility.js`(도면 기반 시설 빌더), `helpers.js`(벽·슬래브·배관 빌더, 셰이더), `aidc-single.html`(단층 원본 + 애드온) |

**설계 원칙 3가지**

1. **단층 원본 불가침** — 원본 코드·모델링·색감은 수정하지 않는다. 필요한 기능(모드 드롭다운, 라벨 토글, 호버 표현 등)은 원본 뒤에 덧붙이는 "애드온" CSS/JS로만 구현
2. **화면 표준은 단층 기준** — 고정 1908×928 디자인 캔버스를 창 크기에 맞춰 비율 축소. 두 모드의 헤더·사이드바·툴바 수치를 픽셀 단위로 일치
3. **도면 좌표 유지** — 모델은 도면 좌표(m)로 짓고, 시인성 확대는 전체 그룹 스케일(가로 1.8배·세로 2.2배)로 처리해 층 판정·라벨·흐름 로직을 건드리지 않음

## 8. Major Revision ④ — 통합 시도와 롤백 (PR #29~#31)

- **시도(A안)**: iframe을 없애고 단층 씬을 React 앱 안에서 직접 그리도록 통합 (#29)
- **문제**: 단층의 색감이 달라짐. 원인은 three.js 버전 차이 — r128은 색 관리가 없고 r169는 sRGB 파이프라인이라 같은 색값이 다르게 렌더링됨
- **보정 시도**: 원본 렌더링 파이프라인을 재현해 밝은 톤 복원 (#30)
- **결정**: 담당자 판단으로 전면 롤백. PR #28 직후 상태와 파일 차이 0줄임을 검증하고 복원 (#31)

**배운 점**: "원본을 그대로 실행"하는 iframe 방식이 가장 안전했다. 이후 "단층 원본 불가침" 원칙이 확정됨. 롤백 중 머지 타이밍이 엇갈려 한 번 더 복원 PR이 필요했던 점도 기록할 만함.

## 10. Major Revision ⑥ — 모델 대확장 (PR #36)

건축 단면계획(종단면도·횡단면도) 4장을 받아 복층 모델만 확장.

- **층고 2.2배** (층 간격 13.5m → 29.7m), **면적 3.24배** (가로·세로 각 1.8배)
- 넓어진 공간에 층별 상세 인프라 추가
  - B1: 수배전 케이블 트레이, 펌프 헤더 배관·밸브, 배관 갤러리, GIS 트렌치
  - 1F: CRAH 급기 덕트, UPS 트레이, 하역장 지게차·팔레트, 로비
  - 2F: 통로별 EOR 캐비닛, 광케이블 트레이, 가스소화 실린더, 발전기실 통로
  - 옥상: 프리쿨링 칠러 가대와 칠러 3기, 냉각탑 급수 헤더

**구현 포인트**: 좌표를 다시 계산하지 않고 그룹 스케일만 씌워서, 기존 층 판정·라벨·흐름 애니메이션이 그대로 동작.

## 11. Major Revision ⑦ — 고해상도·정렬 보정 (PR #37~#39)

- **단층 고해상도 버그**: 고해상도 모니터에서 모델이 우하단으로 밀림. 원인은 캔버스에 CSS 크기 지정이 없어 화면의 2배 크기로 표시된 것. 원본은 건드리지 않고 애드온 CSS 한 줄로 해결 (#37)
- 복층에서 천장만 떠 있던 문제 → 벽 높이를 천장 슬래브까지 올림 (#37)
- 사이드바: 특정 그룹을 펼쳤을 때 하단 그라데이션이 안 나오던 조건 버그 수정 (#38)
- 3D 영역을 아래 5px·오른쪽 7px 이동, 두 모드의 영역 좌표가 완전히 같은지 측정해 검증 (#39)

## 12. Major Revision ⑧ — 시각 표현 고도화 (PR #40~#50)

하루(09-01) 동안 11건. 같은 주제를 여러 번 고쳐 가며 최종 형태를 찾은 구간.

**호버·선택**
- 호버: 색을 바꾸지 않고 검은 외곽 라인만 표시 (복층·단층 공통)
- 선택: 선택한 장비만 원색, 나머지는 흰색을 섞어 밝게(50% → 68% → 80%)

**층별 보기**
- 다른 층 요소가 섞여 보이던 문제 정리 (대지, 잘못 분류된 배관)
- 다른 층의 표현: 완전히 숨김 → 검은 선 60% → 30% → 15%, 장비 선 제외·건물 구조만

**지형(땅) 표현 — 가장 많이 바뀐 부분**
- 대지색 링 → 흰색 덮개 → 블러 띠 → **표면 재질 자체가 투명해지는 셰이더** 순으로 4번 교체
- 각 단계의 실패 이유: 지하 레벨처럼 보임 / 낮은 각도에서 지하를 가림 / 각도에 따라 흰 띠가 건물을 가로지름
- 지형 흙 블록이 각도에 따라 나타났다 사라지는 현상 → 카메라 방향에 따라 연속적으로 투명해지도록 변경

**기타**: Flow 입자 크기·밀도·밝기 상향, Flow를 꺼도 배관은 유지, 사이드바 글자 한두 자가 다음 줄로 떨어지는 현상 방지, 전체 밝기 상향

## 13. Major Revision ⑨ — 마감 정리 (PR #51~#57)

- 내부 칸막이 벽도 천장까지 올림, 벽·슬래브 밝기 추가 상향 (#51, #54)
- 층별 보기의 다른 층 표현을 **두께 없는 건물 외곽 실루엣 라인**으로 확정, 지상면 외곽선 추가 (#51, #52)
- 지상면: 가장자리 그라데이션 제거, 10% 넓혔던 것 취소하고 지하와 같은 크기로 복원, 가느다란 틈 제거 (#51, #53)
- 지하 깊이를 표현하는 흙 볼륨의 끝이 뚝 끊기지 않도록 소산 처리 (#52)
- 1층 보기에서 지하가 같이 보이던 문제 수정 (#54)
- 사이드바 그룹 라벨 위치, 활성 층 표기 굵기 조정 (#55~#56)
- 선택 시 검은 라인이 안 그려지던 장비(UPS 등) 수정, 층 선택 시 Flow 전부 숨김 (#57)

- 측정 기반 정합: 두 모드의 수치를 실제 렌더링 값으로 비교

**시행착오**
- 지상면 표현은 4번 방식을 바꿨고 결국 가장 단순한 형태(클리어한 면)로 돌아옴 → 처음에 참고 이미지를 받고 시작했으면 더 빨랐을 것
- "밝게", "연하게" 같은 정도 표현은 3~4회씩 재조정 → 수치나 비교 대상을 함께 주면 한 번에 끝남
- 통합(A안) 시도와 롤백 → 버전이 다른 렌더링 엔진을 합치기 전에 색감 차이를 먼저 확인했어야 함
- 요청 해석 오류가 몇 차례 있었음(예: 그룹 전체 이동을 항목 간격 축소로 구현) → 지시에 "무엇은 그대로 둘지"를 함께 적으면 예방 가능
